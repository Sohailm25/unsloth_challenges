## Actions

### 1. Problem Analysis
- Read challenge requirements from `challenge_e_memory_efficient_backprop.py`
- Key insight: chunk computation to avoid materializing full logits tensor (4-8GB for 128K vocab)
- Mathematical formulation:
  - Forward: X @ W = logits, then f(logits) = y
  - Backward: dL/dX = dL/dy @ W^T (batched), dL/dW = X^T @ dL/dy (accumulated)

### 2. Oracle Research
- Consulted GPT-5 Pro via Oracle ($2.14 cost)
- Key insights from Oracle:
  - Transform functions should return unreduced per-element values
  - Use `torch.autograd.grad` in backward, not hardcoded derivatives
  - Handle reduction (none/sum/mean) with proper weight normalization
  - Recompute forward in backward with `torch.enable_grad()`

### Key Fixes Made
1. Removed unnecessary `.clone()` on weight in backward - used detach().requires_grad_() instead
2. Changed approach: use autograd.grad ONLY for transformation gradient (dL/d_logits), then apply standard linear formulas
3. Used `torch.addmm` for in-place weight gradient accumulation
4. Recognized that savings appear when N (tokens) is large, not when V is large alone

### Understanding the Memory Savings
- Standard: needs to store [N, V] logits tensor for backward
- Efficient: only stores [chunk_size, V] logits at a time
- Savings = (N - chunk_size) * V * sizeof(dtype)
- With N=4096, chunk=256, V=32K: saves ~240MB
